It generates payloads from composable building blocks, orders them by success probability, and detects blind SSRF through timing and response size side channels. # The 4-Phase Methodology Discovery – Find SSRF-prone parameters and features (URL inputs, file imports, webhooks, PDF renderers) Target – Select internal targets: cloud metadata ( 169.254.169.254 ), internal services, network infrastructure Bypass – Evade URL validation with IP obfuscation (octal, hex, overflow), URL parser confusion (authority tricks, schema manipulation), and protocol smuggling Confirm – Verify exploitation via OOB callbacks, timing differentials, and response content analysis Each phase feeds into the next. When a bypass is blocked, the engine cycles back with alternative techniques. When all bypasses for a target are exhausted, it moves to the next discovery. # Key Capabilities IP obfuscation: decimal, octal, hex, overflow, IPv6 mapping, DNS rebinding URL parser confusion: authority differential, backslash normalization, fragment handling Protocol smuggling: gopher:// , dict:// , file:// , scheme-less URLs Blind detection: timing side channels, response size differential, OOB canary tokens Cloud-aware: AWS, GCP, Azure, DigitalOcean metadata endpoint targeting # Read More For the full technical exploration of the methodology, bypass cascades, and decision trees: Enigma SSRF: An Autonomous Server-Side Request Forgery Engine Links ← Enigma XSS DOMPurify Evolutionary Fuzzer → // comments © 2026 trace37 labs — offensive security research & services · RSS · GitHub
