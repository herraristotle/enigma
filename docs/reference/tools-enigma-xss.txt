It doesn’t guess — it asks questions, observes answers, and adapts. # Demo # The 5-Rotor Methodology Like the original Enigma machine, XSS bypass is the product of five independent decisions — each a “rotor” with multiple positions: Context — Where does input land? (HTML, attribute, script, href, SVG) Blockers — What is the WAF blocking? (Binary search decomposition) Encoding — How should characters be represented? (HTML entities, JS unicode, URL) Structure — What syntax carries the payload? (Parentheses bypass, DOM clobbering) Execution — How does the JavaScript fire? (onerror, ontoggle, popover API) The engine learns from every blocked payload. By the 20th attempt, it has a detailed model of the WAF’s behaviour and navigates a narrowing possibility space with increasingly precise information. # Usage # Basic reflected XSS scan enigma run "https://target.com/search" "q" # With authentication enigma run "https://target.com/search" "q" --cookie = "session=abc123" # DOM XSS via URL hash enigma run "https://target.com/#" "hash" --source = hash # Stored XSS with observation enigma run "https://target.com/comment" "comment" \ --observe = "https://target.com/post/123" # Read More For a deep technical exploration of the methodology, cascade logic, and decision trees: Enigma: An Autonomous XSS Engine Built on a 5-Rotor Methodology Watch the 5 rotors adapt in real-time as they probe, decompose, and bypass a WAF: Inside Enigma: How 5 Rotors Crack WAF-Protected XSS Links ← Mastermind AI Enigma SSRF → // comments © 2026 trace37 labs — offensive security research & services · RSS · GitHub
